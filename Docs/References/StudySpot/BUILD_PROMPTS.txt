PRODUCT
Audience: students who want to find and remember places suitable for studying.
Purpose: discover candidate places, view them geographically, save personal
study observations and compare places using one's own completed study sessions.
Five main screens: Explore, Map, Place Details, Saved Places, My Progress.
Additional add/edit forms may be sheets, not separate main screens.
MapKit is the meaningful advanced-framework integration accepted by the brief.

Explore: search libraries/cafes by text and a selected map area; list results.
Map: markers, current selected region, selected-place detail navigation.
Place Details: name/address where supplied, location, save action, personal
notes, study preference observations and a form to log a completed session.
Saved Places: search/filter my saved observations, edit notes and remove a
saved flag. Removing a favourite must not silently erase session history.
My Progress: total minutes, number of sessions, per-place study totals and
recent sessions with edit/delete. Keep graphs simple and accessible.

Use MKLocalSearch for real place search. Default map region can be Colombo;
search in the visible area when the user requests it. Current location is
optional and starts only after the user selects Near Me. Add a meaningful
NSLocationWhenInUseUsageDescription. Denied/restricted location must not block
manual search or saved data. Handle loading, empty results, errors and retry.
Cancel obsolete search requests and prevent stale results replacing newer ones.

Do not invent Wi-Fi, opening hours, quietness, prices or live seat availability
from MapKit results. Personal Wi-Fi/power/quietness observations have an Unknown
default and are explicitly labelled as the user's notes, not verified facts.
Keep a small clearly labelled fictional demo dataset for UI tests/demos.
Live results and demo data must remain distinguishable; do not silently switch
to invented results on a network failure. A demo dataset can be seeded once
only when a deliberate demo mode or UI-test launch argument is selected.

DATA
Use Core Data, not UserDefaults/JSON as the principal persistence mechanism.
Use an actual .xcdatamodeld model and explicit NSManagedObject subclasses with
manual code generation to avoid duplicate generated class definitions.
Place entity: stable app UUID, optional provider identifier, name, address,
latitude, longitude, category, isSaved, createdAt, updatedAt, personal notes,
and tri-state/personal observations. Document practical deduplication when
provider identifiers are absent; do not create duplicates on every save.
StudySession entity: UUID, completedAt, durationMinutes (1...240), focusRating
(1...5), optional notes, and a required relationship to Place with an inverse.
Explain deletion rules. Saving a session retains its place even if unfavourited.
If permanent place deletion is offered, disclose related-session deletion
and require confirmation. Provide session editing/deletion for genuine CRUD.
Use a persistent store for app use and an injected in-memory store for tests.
Handle store failures with an actionable error instead of crashing or silently
deleting the database. Configure lightweight migration for compatible changes.
